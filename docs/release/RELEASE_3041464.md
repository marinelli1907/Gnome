## What this release contains (since the last shipped web/app builds)

- **0087 is already live in production** (applied 2026-08-13 under the
  controlled sequence): `profiles` is owner/admin-only; other users read the
  `public_profiles` allowlist view. The blanket world-readable policy is gone.
- `gnome-assistant` **v3 is already deployed** (syntax-only recovery parser).
- What is **waiting on these releases**:
  - **Mobile (expo/)**: reads `public_profiles` (required post-0087), new
    `Gnome AI` tab, onboarding welcome chat, profile editor with private
    contact fields, drafts review with in-place editing and retry.
  - **Web (web/)**: LoginClient account view now collects first/last/email/
    optional phone through `save_onboarding_contact` and no longer writes a
    free-text display name onto the world-readable profile row.

Order matters only in one direction and it is already satisfied: the migration
had to precede the clients, and it did. The currently-installed old mobile
build keeps working because `authenticated` still holds the pre-0087 column
grants on `profiles`; its embedded owner reads return rows via… **no — note
carefully:** the old build embeds `owner:profiles(...)`, and after 0087 a
non-admin gets zero rows for other users, so on the OLD build other sellers'
names/avatars render blank in Browse. That is a cosmetic degradation, not an
error, and it is the reason the mobile rebuild should happen soon.
